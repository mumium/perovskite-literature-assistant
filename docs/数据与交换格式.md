# 数据结构与分析包格式

当前数据库 `PRAGMA user_version=2`，交换 `schema_version="1.0"` 保持兼容。v1库打开时先用SQLite一致性备份保存到 `migrations/library-v1-UUID.sqlite`，再以事务新增高亮和阅读状态表，保留旧文献、附件、分析、历史。程序拒绝打开高于支持版本的库。v1→v2已使用按v1结构构造的旧库副本测试。

## 数据目录

v0.5增加独立启动位置记录 `startup-location.json`，优先位于exe所在目录（Python版源码根目录），只读时位于本机LOCALAPPDATA/PerovskiteLiteratureAssistant。结构为 `schema_version=1`、`data_directory`、`relative`、`saved_at_ns`；只保存最近成功打开的库位置，同盘便携路径优先相对，备用位置使用绝对路径。它不属于文献内容/分析配置，不进入分析包或完整数据备份，不写注册表或临时解包目录。正文、SI、数据库与应用配置仍在下面的数据目录中。

| 路径 | 用途 |
|---|---|
| library.sqlite | 元数据、候选、附件登记、关联、分析段、历史、FTS索引 |
| config.json | 非敏感API配置，默认api_enabled=false，无Key |
| files/哈希前缀/file_id.扩展名 | 原件的受管理副本，SHA256全局唯一 |
| exchanges/package_id.json | 导出时的全附件文本快照及包登记 |
| results/ | 导回JSON、批次报告和候选 |
| api_jobs/请求签名/ | 分块提取断点、用量、最终结果，无Key |
| .library.lock | 当前进程数据目录锁；正常退出移除 |
| migrations/ | 升级前数据库快照，完整备份包含此目录 |
| annotated/ | 默认另存的带标准PDF批注文件 |
| pdf_exports/file_id/输出SHA256.json | PDF写入记录，绑定原文件ID/哈希和结果哈希，不保存外部绝对路径 |
| pdf_backups/file_id/UUID.pdf | 覆盖目标文件前的原件备份，完整备份包含此目录 |

文章、文件、包和历史ID使用UUID。附件哈希相同则跳过，导入与解析不会修改或删除原件。v0.3允许用户明确选择外部原PDF写入标准批注，写入前备份；受管理附件保持不变。同DOI文件可以共存，人工确认后赋正文/版本/预印本/SI角色。文章无附件时保留历史，不自动删除。

## 关系和修订

文件选择关联以当前article_id为明确目标，后台逐文件调用哈希去重、导入与关联。已有文件移动关联时保留file_id、哈希、原分析内容和历史，原/新文献的核验标记失效；同article_id、同角色且已确认时为幂等复用，不重复使核验失效。批次报告存results/attach-report-UUID.json，包含文件名、file_id、目标/原article_id、复用与解析状态、失败原因，不保存外部原文件的绝对路径。

- articles: article_id、metadata JSON、candidates JSON、notes、created。
- files: file_id、sha256唯一、name、相对path、status、reason、完整extracted JSON。
- links: 一个文件当前属于一个article_id，role、pairing依据、confirmed；一篇文章有多个文件。
- proposals: 配对待确认队列，源file_id、候选article_id、依据、resolved。
- sections: (article_id,name)唯一，name为story/process，content、evidence、checks、human_verified、modified。
- 工艺关系在process JSON内：文章 → samples[]（sample_id/label/group）→ steps[]（order/category/description/parameters/evidence_ids）；performance[]独立引用sample_id，每条记录有独立conditions及values。
- history: 记录范围、旧值、新值、来源、UTC时间。人工修订保留历史。配对/角色变化保留分析内容但撤销核验与引用匹配标记。
- packages/imports: 登记交换快照、完整结果及校验/应用报告，用于拒绝错文章结果及重复导入识别。先导入部分段后可再导入同一JSON未选段；已处理段不重复覆盖。
- search_index: SQLite FTS5覆盖全部提取文本、元数据、故事、工艺、笔记；LIKE补充中文与任意子串。
- highlights: mark_id、file_id、file_sha256、kind、text、anchors JSON、color、note、created、modified。PDF anchors为实际page_index和未旋转PDF坐标rect；显示时按页面rotation_matrix变换，因此缩放/旋转显示不改变保存位置。DOCX anchors为loc_id和Python字符start/end（右开区间）；界面与Qt UTF-16光标偏移显式换算。标记与原件分离，全文索引含高亮和批注。
- reader_state: 每个file_id的最后实际page_index、zoom比例和zoom_mode（fit/manual），自动保存阅读位置。高亮删除/修改记入history，不影响分析段的人工核验状态。
- PDF原生批注使用Highlight类型，subject中以 `PLA:file_id:source_sha256:mark_id` 标识归属，content保存中文/英文批注。重复写入只替换同文件同来源的本工具标注，其他来源的标注不删除。先写同目录临时PDF、重开校验注释与评论、计算哈希、备份已有目标，再原子替换。已有目标只接受原文原哈希或此前记录的本工具输出哈希；外部改动后拒绝覆盖。写入记录含prepared/saved状态与相对备份路径。

## 元数据

schema.py 的 META_FIELDS 列出完整字段。作者、共同第一作者、通讯作者、单位、标签为字符串数组；si_complete为true/false/null；其余为字符串/null，年份也为字符串。日期允许YYYY、YYYY-MM、YYYY-MM-DD，合法日期验证，不补造月日。

candidates中每次候选有source、location（本地可用时）、values和检索时间（联网）；人工采用时直接编辑metadata，旧值和新值保留于history。元数据候选与修订源在Excel中保留，不把Crossref索引日期用于发表时间。身份来源不足时留空。

## ZIP分析包

`manifest.json` 包含schema_version、package_id、article_id、metadata、metadata_candidates和files。files每项含file_id、sha256、角色、名称、状态、说明、配对依据、**全部locations文本**。即使不支持的DOC也列出，locations为空，状态不得省略。包不含原始二进制附件与Key；图片表格需要用户另提供原件核验。

位置规则：PDF `pdf:p0:c0` 表示实际第1页第1文本块，page_index=0，printed_page未知为null；DOCX `docx:p4:c0` 表示第5段，`docx:t0:r1:c0` 表示第1表第2行的第1块。DOCX不保存稳定页码。单位置超过9000字符分块，所有字符连续保留，无静默截断。

`prompt.txt` 是内置分析提示词；`result-schema.json` 是可机器校验的字段格式；`result-template.json` 填充了真实ID和哈希。模板中的空数组只演示结构，不能作为已完成结果导回。

## JSON结果

根字段严格为schema_version、package_id、article_id、file_hashes、evidence、sections。file_hashes必须与导出时和当前文章全部附件完全一致，导入还会计算当前附件实际哈希。重新配对或添加SI后须重新导出。

sections可只含story、只含process或两者。story有one_sentence、background、strategy、mechanism、evidence_chain、benefits、novelty、limitations、relevance，每项为声明数组。声明含text、kind、evidence_ids。kind只有author_claim/direct_result/ai_inference，前两类必须引用证据。

工艺参数及性能values每项字段如下（全部保留，未知填null）：

| 字段 | 类型与含义 |
|---|---|
| name | 参数名称，如退火温度、添加剂用量、PCE、Voc、Jsc、FF |
| original_value | 原文字符串、数值或null |
| original_unit | 原文单位或null |
| normalized_value / normalized_unit | 标准化数值/单位，未知null |
| basis | 百分比/比例的计算基准，未知null，不假设是质量或摩尔 |
| conversion_note | 换算依据，提供标准化值时必须有说明 |
| conflict_group | 正文/SI冲突的共同标识，两值分别保留 |
| evidence_ids | 证据ID数组，参数有值时必填非空 |

performance每条含record_id、sample_id、measurement_kind、conditions、values、evidence_ids。测量类型区分冠军/平均/正反扫/稳定输出/认证/EQE/稳定性等；conditions存扫描速率、面积、封装、气氛、温度、湿度、光照、工作状态等。未报告的重要参数用null参数行保留，不能把未知值写0。

evidence每项含evidence_id、file_id、loc_id、quote、figure、printed_page。先验证文件归属和位置，再按去空白、软连字符与常见连字归一后的子串匹配引用。短引用或匹配成功都不证明提取语义正确。DOCX的printed_page必须null。未匹配引用可保存为待核验，但不能人工标记整段已核验。

导入顺序：严格JSON解析（拒绝NaN与重复键）→ schema/类型→包与文章→清单/哈希→样品/性能关系→来源和引用→差异预览→所选段事务应用。已人工核验段只保存新候选，不自动覆盖。引用匹配成功的AI内容仍为人工待核验。

Excel导出文献、附件、样品工艺、性能、证据、阅读卡、修订历史、高亮批注八张关联表。原始数值保持数值类型，缺失为真正空单元格；JSON列明确标记。长单元格按30000字符续行，所有内容保留。公式前缀文本转义，避免将论文文本执行为Excel公式。
